TurtleBot3 Lab

A browser control page for a TurtleBot3 robot, a safety layer that is the only thing allowed to move the wheels, and swappable control systems that students write in Python — developed and tested against a simulated robot until the real robot is available.

Simulated robot: working Real robot: not yet connected Code: merged to main Control page v0.3.0 Reviews: pending Status as of 17 Nov 2026

Where it runs

The control page does not open from this website. A web page served over https:// is not allowed to open the plain ws:// connection the robot uses, so the page is served from the laptop (simulated robot) or, later, from the robot's Raspberry Pi on the robot's Wi-Fi. This page explains the project and links to it.
  1. Web page — a live arena view of the robot's world with the controller's reasoning drawn on it, a race mode, an instrument bench, and an always-visible E-STOP.
  2. Controller host — runs one student controller at a time, each in its own process; a controller that hangs for more than 0.5 s is stopped and idle takes over.
  3. Safety layer — the only source of wheel commands: speed limit 0.10 m/s and 1.0 rad/s, 0.5 s watchdog, latched e-stop, stop if an obstacle is closer than 0.20 m ahead.
  4. Robot — the simulated TurtleBot3 on a laptop today; the real TurtleBot3 (ROS 2) later.

What it does today

The arena view

  • The robot's world fills the screen. The robot is drawn where its odometry says it is; in the simulator the true walls and true position sit faintly underneath, so students can watch odometry drift.
  • LiDAR rays in real time, and a LiDAR map that builds up as the robot drives.
  • Asked versus sent: a dashed arc shows where the controller asked to go in the next 1.5 s, a solid arc what the safety layer actually sent. When they differ, a banner says why and the stop zone ahead of the robot turns solid.
  • The controller's reasoning, drawn on the map and stated in words: the gaps goal_seek is weighing and the one it chose, the wall distance wall_follow is holding, the sectors obstacle_avoid is watching. Students' own controllers can do the same.
  • Speed dial (measured, asked, safety limit), a LiDAR radar sweeping at the sensor's 5 Hz, battery.
  • Click the map to set a goal. When the simulator page opens idle, a short demo plays until someone takes over.

Race mode

  • Pick up to four controllers; each drives the same arena from the same start in simulated time (faster than real time, same safety layer), then they replay together as coloured ghosts with a leaderboard and a timeline.
  • Timed runs of the live robot are scored automatically — goal reached, time, path length, collisions, closest approach, safety interventions — and ranked.

The instrument bench

  • A two-channel scope: speed asked, sent and measured on channel 1; any signal on channel 2, including a controller's internal values (e.g. wall_follow's PID error and P, I, D terms). Hover for values, hold, record to CSV.
  • A console showing each controller's print() output and errors.

Controllers

  • Built in: teleop, obstacle_avoid, wall_follow (PID, gains editable live), goal_seek, plus idle and a watchdog demonstration.
  • Students write a controller as one short Python function, step(s), that returns a forward speed and a turn rate. Each runs in its own process; one that hangs for more than 0.5 s is stopped.
  • Three simulated arenas (room, maze, open field) with goal pads; a Burger or Waffle Pi robot.
  • Repeatable experiments faster than real time from the command line, with CSV logs for analysis.

Honest limits of the simulator

The simulated robot is a simple 2-D model: acceleration limits, LiDAR with noise, wheel-encoder and IMU odometry that drifts. It does not model motor current, floor slip, sensor dropouts, Wi-Fi delay or the camera. Anything that depends on those must be checked on the real robot.

Run it on a laptop

Needs Python 3.10 or newer, Git, and access to the private ece-utulsa/turtlebot3-lab repository. In PowerShell:

git clone https://github.com/ece-utulsa/turtlebot3-lab.git
cd turtlebot3-lab
powershell -ExecutionPolicy Bypass -File .\setup.ps1
powershell -ExecutionPolicy Bypass -File .\run_mock.ps1

The control page opens at http://localhost:8080/. Press Ctrl+C in the PowerShell window to stop everything. Options: --model waffle_pi, --arena maze or --arena open_field.

Compare controllers without the page:

.\.venv\Scripts\python.exe -m tblab.runner -c goal_seek,obstacle_avoid,wall_follow --arena open_field
