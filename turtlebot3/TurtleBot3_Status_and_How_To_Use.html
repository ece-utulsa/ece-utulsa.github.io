How it works

Only the safety layer moves the wheels

Control pageyour browser · drive, watch, E-STOP
Controller hostruns ONE controller · kills it if stuck > 0.5 s
Safety layerclamp speed · watchdog · E-STOP · obstacle stop
Robotsimulated today · TurtleBot3 later

asks: /cmd_vel_request

sends: /cmd_vel

A controller only asks for a speed. The safety layer decides what reaches the wheels: at most 0.10 m/s and 1.0 rad/s, a stop if commands go quiet for 0.5 s, a stop if anything is within 0.20 m ahead, and an E-STOP that stays latched until you clear it.

All of it talks through rosbridge: ROS messages as text over a web socket. The page does not change when the real robot replaces the simulated one; only the address does.

Safety · E-STOP pressed

E-STOP latches

Button, Space or Esc. The bar turns red and the speed drops to 0.000. The robot stays stopped, even if a controller keeps asking to move, until you press Clear e-stop.

After clearing, nothing moves until a fresh command arrives.

Tested automatically and by hand in the simulator. On the robot it is the first thing tested, with the wheels off the floor.

How to use it · Windows laptop

Run the simulator in four steps

1

In File Explorer, open the turtlebot3-lab folder, click the address bar, type powershell and press Enter.

2

Get the latest code (any time):

git pull
3

One-time setup (makes .venv and runs the tests):

powershell -ExecutionPolicy Bypass -File .\setup.ps1
4

Start everything (the browser opens by itself):

powershell -ExecutionPolicy Bypass -File .\run_mock.ps1

Then

  • Press any key or click the map to take over from the demo
  • Hold the arrows to drive
  • Click a controller to switch
  • Click the map to set a goal

To stop

Robot: E-STOP.
Everything: Ctrl+C in the PowerShell window.

Options: --arena maze, --arena open_field, --model waffle_pi

For students

A controller is one small Python file

# controllers/spin.py
NAME = "spin"
VERSION = "1.0.0"          # bump on every change
PARAMS = {"rate": 0.3}     # editable on the page

def setup():               # when switched on
    print("spin started")  # shows in the Console

def step(s):               # 10 times a second
    return 0.0, PARAMS["rate"]
    # (forward m/s, turn rad/s)
1

Copy templates/my_controller.py into controllers/ and rename it.

2

s holds the sensors: s.scan, s.odom, s.imu_yaw, s.goal_vector().

3

Restart run_mock; it appears in the controller list.

4

If step() crashes or takes longer than 0.5 s, the robot stops and idle takes over.

Built in: idle · teleop · obstacle_avoid · wall_follow (PID) · goal_seek · demo_runaway (deliberately hangs, to show the watchdog) · onnx_policy (placeholder for the AI controller)

Downloading to the TurtleBot

The deploy script is ready, with copying switched off

1

Runs the 103 tests. A failure stops it.

2

Checks every controller loads and has a version.

3

Builds a bundle with a manifest: each controller's name, version and fingerprint, plus the code version.

4

Copies it to the Pi over SSH (secure remote login) and restarts the controller host. This step is off until robot day.

Code only reaches the robot this way. The web page never accepts code.

Robot day · on the laptop, on the robot's Wi-Fi

Four steps, with no motion until step 3

1

Inventory

Read only. ROS version, robot model, LiDAR, memory, topics. Stop and report. If the robot runs ROS 1 Noetic (end of life May 2025), you decide whether to keep it or re-flash.

2

Install

Only after your go-ahead and an SD-card backup. Install rosbridge, switch on real deploy, serve the page from the Pi.

3

First motion

On a stand, wheels off the floor. E-STOP first, then hold-to-drive, watchdog, obstacle stop, runaway controller. Then on the floor at 0.10 m/s.

4

Calibrate

Record speed steps and a 1 m square. Tune the simulator to match the real robot.

Bring: robot, charged battery and charger, a stand, a spare microSD card and reader, the Pi's login (you type the password), the Wi-Fi details, and an HDMI monitor and keyboard just in case.

Full list: docs/robot_session_checklist.md in turtlebot3-lab
